Self-Hosted PaaS · Edge Reverse Proxy · Zero Daemons

Deploy apps on a 1GB server without triggering the OOM killer

The Linux Out-Of-Memory (OOM) killer is the kernel's emergency mechanism. When physical RAM and swap are exhausted, the kernel violently terminates the largest process on your machine, usually your database, to keep the operating system alive.

Traditional PaaS stacks eat 600MB+ before you deploy a single service. Bifrost packs the orchestrator, SQLite, TLS, and reverse proxy into a single 11MB binary that idles at 14MB of resident memory, leaving 900MB+ for your actual code.

The 1GB server dilemma

You claim a free tier cloud instance. You set up a self-hosted platform so you can push code like Vercel or Railway without paying monthly subscription tiers.

You run the standard install. Minutes later, the server stops responding. SSH hangs. The control plane booted a PostgreSQL database, a Redis cache, a queue manager, an external Traefik proxy, and a PHP-FPM API server. Total idle memory consumed: 650MB.

Then your first deployment triggers npm run build. Vite or webpack allocates 500MB during bundling. The kernel runs out of memory, triggers the OOM killer, and panics your machine.

Bifrost was built to end this exact failure mode.

Architecture & Internal Primitives

How Bifrost achieves sub-15MB idle footprints without sacrificing capability.

Zero-Daemon Reverse Proxying

Eliminates Traefik and Caddy containers (saves 60MB RAM).

internal/proxy

Running external reverse proxies like Traefik or Caddy requires a dedicated container, inter-process network bridging, and periodic docker label discovery. Bifrost embeds Go's battle-tested net/http/httputil.ReverseProxy directly in the main process.

// Zero-allocation 32KB buffer pooling stops garbage collector spikes
type bufferPool struct { pool sync.Pool }
func (bp *bufferPool) Get() []byte { return *(bp.pool.Get().(*[]byte)) }
func (bp *bufferPool) Put(b []byte) { bp.pool.Put(&b) }
  • Lock-Free Routing: Route lookups are stored in an atomic.Pointer for zero-contention read throughput.
  • Automated TLS: Automatic Let's Encrypt certificates via golang.org/x/crypto/acme/autocert on ports 80 and 443.
  • Static Direct Serve: Static SPA apps bypass containers entirely; files are served directly with gzip streaming and SPA index.html fallbacks.

Remote Artifact Deployment (0MB Server Build RAM)

Offload heavy bundling to GitHub's free 7GB runners.

internal/builder

Running npm run build or Docker buildx on a 1GB host inevitably spikes memory by 600MB–1.2GB. Bifrost introduces the remote artifact pattern:

1. Developer pushes to GitHub (main branch)
2. GitHub Actions runs build on 7GB runner (npm ci && npm run build)
3. Runner streams tarball to Bifrost: POST /api/v1/projects/:id/deploy/artifact
4. Bifrost extracts to disk (5MB RAM) and hot-swaps routing pointer in <1 second

For users who prefer direct Git webhooks without GitHub Actions, Bifrost provides a guarded local fallback: a global single-concurrency lock with NODE_OPTIONS="--max-old-space-size=384" to keep V8 inside host bounds.

Lean Unix Domain Socket Client

Zero SDK dependencies; native Kiri and Docker engine compatibility.

internal/runtime

The official Docker Go SDK pulls in dozens of packages (gRPC, OpenTelemetry, containerd), adding 15MB to the binary and substantial heap allocations. Bifrost uses a specialized 300-line HTTP client over Unix sockets (/var/run/kiri.sock or /var/run/docker.sock).

transport := &http.Transport{
  DialContext: func(ctx context.Context, _, _ string) (net.Conn, error) {
    return (&net.Dialer{}).DialContext(ctx, "unix", socketPath)
  },
}

Auto-detects Kiri (a 15MB Rust container daemon) or standard Docker, and automatically injects hard cgroup memory ceilings (MemoryLimitMB) on every container spawned.

Embedded Database with Bounded Page Cache

Pure Go SQLite with low-memory connection pragmas.

internal/store

PostgreSQL consumes 80MB–120MB even with zero active queries. Bifrost uses embedded pure Go SQLite (modernc.org/sqlite) with CGO disabled, configured with aggressive memory pragmas:

PRAGMA journal_mode = WAL;      -- Concurrent non-blocking reads
PRAGMA cache_size = -2000;     -- Caps page cache at strictly 2MB
PRAGMA temp_store = FILE;      -- Sort tables buffer to disk, not RAM
PRAGMA mmap_size = 0;          -- Disables virtual memory bloat

The entire state database is stored in a single file (/var/lib/bifrost/bifrost.db), making backups as straightforward as copying one file.

Getting Started

Bifrost runs on any Ubuntu or Debian Linux server (x86_64 or ARM64). The installer automatically configures a 2GB swapfile if low RAM is detected:

// Install and launch systemd service
curl -sSL https://baliga.dev/bifrost/install.sh | sudo bash

Once installed, open http://YOUR_SERVER_IP:80 to manage applications and view real-time host telemetry.
